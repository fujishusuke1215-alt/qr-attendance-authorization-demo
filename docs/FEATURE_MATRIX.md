# Feature acceptance matrix

This matrix was written before implementation from the current `main` branch
of `backend-design-case-studies/qr-attendance-authorization/` and the requested
acceptance criteria. Results are updated after implementation and verification.

| Reference capability / acceptance requirement | New implementation location | New test(s) | Result |
|---|---|---|---|
| Stable HMAC QR per action/site/revision; admin rotation invalidates the previous revision | `backend/src/qr/`, `backend/src/api/qr.rs`, `frontend/src/features/qr/` | `token_is_deterministic_for_same_inputs`; `token_changes_with_key_kind_site_or_revision`; `invalid_key_and_token_are_rejected_without_secret_output`; `postgres_acceptance_covers_auth_attendance_qr_permissions_and_hr_reconciliation` (rotation, stale revision, old QR) | Local token tests pass; rotation awaits PostgreSQL CI |
| Check-in and check-out are separate; QR replay and duplicate-day rules are explicit | `backend/src/attendance/`, `backend/migrations/`, `frontend/src/features/attendance/` | `attendance_day_uses_tokyo_midnight_boundary`; `postgres_acceptance_covers_auth_attendance_qr_permissions_and_hr_reconciliation` (create, retry, duplicate, incomplete profile) | Local unit tests pass; database cases await PostgreSQL CI |
| HR snapshot includes department hierarchy, employee affiliations and job codes; validates before writes | `backend/src/hr/`, `backend/src/org/`, `backend/src/sync/`, `backend/fixtures/hr_snapshot.json` | `snapshot_rejects_missing_required_fields_before_reconciliation`; `incomplete_snapshot_cannot_remove_existing_grants`; `postgres_acceptance_covers_auth_attendance_qr_permissions_and_hr_reconciliation` (invalid snapshot preserves grants) | Local validation tests pass; database case awaits PostgreSQL CI |
| Department identity survives rename/reparent; names do not identify groups; code migration is explicit | `backend/src/org/`, `backend/src/sync/` | `department_identity_survives_name_and_parent_changes`; `same_name_with_different_identity_codes_stays_distinct`; `explicit_alias_codes_resolve_to_one_identity` | Pass (Rust unit tests) |
| Sync is staged, observable, repeatable, and produces no duplicate grants/audit on identical input | `backend/src/sync/`, `backend/migrations/`, `frontend/src/features/hr-sync/` | `postgres_acceptance_covers_auth_attendance_qr_permissions_and_hr_reconciliation` (all success stages, repeat snapshot, unchanged audit count, validation failure stages) | Database cases await PostgreSQL CI; progress UI test passes locally |
| HR role scopes and manual grants remain independent; stale HR grants alone are revoked | `backend/src/authz/`, `backend/src/sync/`, `frontend/src/features/permissions/` | `automatic_sync_preserves_manual_grant`; `promotion_revokes_only_stale_automatic_scope`; `postgres_acceptance_covers_auth_attendance_qr_permissions_and_hr_reconciliation` (manual remains, automatic revoked) | Policy unit tests pass; reconciliation awaits PostgreSQL CI |
| Backend enforces authorization for every protected endpoint; manual changes are audited | `backend/src/authz/`, `backend/src/api/`, `backend/migrations/` | `postgres_acceptance_covers_auth_attendance_qr_permissions_and_hr_reconciliation` (unauthorized admin call, manual grant/revoke audit) | Database cases await PostgreSQL CI |
| Entra/MSAL and local development auth use adapters; invalid return destinations are rejected | `backend/src/auth/`, `frontend/src/auth/`, `frontend/src/app/` | `development_adapter_requires_a_valid_demo_identity`; `dev_auth_is_disabled_outside_development_mode`; `login_return_target_rejects_external_urls`; Entra JWT/JWKS verification is implemented but has no isolated signature-fixture test | Local adapter and redirect tests pass; Entra token behavior is not independently tested |
| Incomplete auth/profile never creates a punch; mobile scan flow reports errors | `backend/src/auth/`, `frontend/src/features/attendance/` | `profile_load_failure_never_posts_attendance`; `empty_profile_never_posts_attendance`; `scan_reuses_idempotency_key_after_retry`; `postgres_acceptance_covers_auth_attendance_qr_permissions_and_hr_reconciliation` (401/422 and no row) | Frontend and local profile unit tests pass; DB cases await PostgreSQL CI |
| Admin UI exposes department tree, grant source, QR rotation confirmation and sync stages/failure details | `frontend/src/features/{permissions,qr,hr-sync}/` | `department_tree_selects_active_descendants_only`; `qr_rotation_requires_confirmation`; `permission_rows_expose_grant_source`; `sync_view_renders_stage_and_failure_detail` | Pass (6 frontend test files, 9 tests) |
| REST/OpenAPI, PostgreSQL migrations and seed, Docker Compose, CI and tagged GHCR release | `backend/src/api/`, `docs/openapi.yaml`, `backend/migrations/`, `docker-compose.yml`, `.github/workflows/` | `cargo test --locked --all-targets`; `pnpm typecheck`; `pnpm test`; `pnpm build`; GitHub Actions Docker image build | Rust 17 unit tests and frontend checks pass locally; local PostgreSQL and Docker unavailable; CI awaits remote run |

The local Rust test command reports the PostgreSQL acceptance test as passed when
no `TEST_DATABASE_URL`/`DATABASE_URL` is configured because it exits early after
printing a diagnostic. In this workspace no local PostgreSQL service or Docker
engine is available, so only the 17 database-independent Rust tests ran locally.
The CI workflow sets `TEST_DATABASE_URL` against its PostgreSQL service and runs
the full acceptance test; its result will be reflected after the first GitHub run.
